# Постоянные сохранения Integrals: Remake

Игра публикуется по адресу <https://blumbutta.github.io/integrals-remake/>. Облачные профили и общий рейтинг обслуживает существующий `kozlogon-server`: API находится по пути `/integrals-api`. Kozlogon продолжает использовать `/ws`, CubeBomber — `/cube-ws`.

В базе SQLite сервер хранит прогресс, имена, настройки участия в рейтинге и хеши кодов восстановления. Сервер сам рассчитывает доход и проверяет покупки; клиент не передаёт готовый итоговый счёт. Без настроенного постоянного хранилища облачный API отвечает `503 storage_unavailable`, а сервер двух других игр продолжает работать. Прогресс локального режима хранится в браузере и не входит во всемирный рейтинг.

## Настройка на Render

Добавление диска — отдельное платное изменение. В `render.yaml` оно намеренно не включено автоматически. Ориентир: **1 GB за $0.25 в месяц**, дополнительно к текущему серверу; перед подключением проверь сумму в [актуальном тарифе Render](https://render.com/pricing).

После согласования расходов настрой существующий сервис **kozlogon-server**:

| Настройка | Значение |
| --- | --- |
| Disk name | `integrals-saves` |
| Mount path | `/var/data/integrals` |
| Size | `1 GB` |
| Environment variable | `INTEGRALS_DB_PATH=/var/data/integrals/game.sqlite` |
| Node.js | `24.x` — встроенный `node:sqlite` |
| Service health check | `/health` — оставить существующую проверку всех игр |

Путь переменной должен находиться внутри подключённого диска. Указание абсолютного пути само по себе не создаёт постоянное хранилище: обычная файловая система Render теряется при перезапуске и развёртывании. Приложение создаёт папку и таблицы SQLite при первом запуске; файл базы и его `-wal`/`-shm` находятся в одном каталоге.

Подключение диска запускает развёртывание сервиса. Диск доступен одному экземпляру, отключает развёртывание без простоя и приводит к короткой остановке **всех трёх игр** при обновлении общего сервера. Текущие комнаты Kozlogon и CubeBomber при перезапуске теряются, как и раньше. Эти ограничения описаны в [документации Render](https://render.com/docs/disks).

## Проверка после подключения

1. `GET https://kozlogon-server.onrender.com/health` должен вернуть `200` и `{"ok":true}`.
2. `GET https://kozlogon-server.onrender.com/cube-health` должен сохранить прежние ограничения: 6 игроков, 4 комнаты и 1 активная комната.
3. `GET https://kozlogon-server.onrender.com/integrals-api/health` должен вернуть `200`, `game: "integrals-remake"` и `storage: "persistent"`.
4. В игре создай облачный профиль, получи несколько интегралов, сохрани код восстановления. После перезапуска сервиса восстанови этот профиль: прогресс и место в рейтинге должны сохраниться.

При `503` проверь подключение диска, переменную окружения и права каталога. Не заменяй путь временной папкой: это создаст видимость работающих сохранений, которые исчезнут после следующего развёртывания. Сервер не записывает коды восстановления и пути базы в логи ошибок.

## Резервные копии и обслуживание

Для SQLite используй согласованную резервную копию через SQLite Backup API или `VACUUM INTO` в отдельный файл и скачай копию с сервиса. Простое копирование только `game.sqlite` при работающем сервере может пропустить изменения в WAL. Периодические снимки диска Render не заменяют резервные копии базы: Render предостерегает от восстановления дискового снимка пользовательской СУБД из-за риска повреждения данных.

Код восстановления профиля даёт доступ к его прогрессу. Не публикуй коды и содержимое базы; выдавай файлы резервных копий только владельцу сервиса. При выключении процесса сервер сначала завершает HTTP-запросы, затем выполняет контрольную точку WAL и закрывает SQLite.

## Локальная проверка общей сборки

```sh
pnpm install --frozen-lockfile
pnpm run build:server
INTEGRALS_DB_PATH="$PWD/local-integrals.sqlite" npm run start:server
```

Не добавляй `*.sqlite`, `*.sqlite-wal` и `*.sqlite-shm` в Git. Для регрессии общего сервера: `node --test tests/shared-server.test.mjs`. Тест запускает готовый `server/index.mjs` на свободном локальном порту и проверяет прежние HTTP/WebSocket-маршруты, лимиты комнат и подключений, отказ API без диска и сохранение профиля после перезапуска.
